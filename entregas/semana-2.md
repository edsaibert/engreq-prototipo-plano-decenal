# Documento de entregas feitas na semana-2

## User Stories

Foram desenvolvidas doze User Stories buscando cobrir todos os requisitos funcionais. Para cada User Storie existe:

- Indentificador: padrão US<número da user storie>, por exemplo: US01, US02
- Nome: para dar uma breve ideia da funcionalidade que a US cobre
- Descrição: é a user storie em si
- Prioridade: se a funcionalidade é obrigatória, importante ou desejável
- Critérios de validação: o que precisa para validar aquela funcionalidade
- Vínculo com requisitos: com quais requisitos aquela US se relaciona
- Vínculo com telas do protótipo: ainda não definido para nenhuma US, pois ainda não foi definido quais telas o protótipo vai ter

## Casos de Uso

Foram levantados quatorze Casos de Uso para o sistema, analisando as principais ações dos usuários dentro do escopo apresentado pelos requisitos. Os Casos de Uso seguem a seguinte estrutura:

- Identificador: padrão UC<número do caso de uso>, por exemplo: UC01, UC02
- Nome: indica ação dos atores, sempre no infinitivo
- Ator principal: ator que realiza a ação efetivamente
- Pré-condições: estados dos atores ou entidades no sistema que precisam existir para que o caso de uso ocorra
- Fluxo Principal: sequência de passos efetuadas para atingir o resultado esperado
- Fluxo Alternativo: representa desvios do fluxo principal
- Pós-condição: estado do sistema após a conclusão da tarefa

## Regras de Negócio

Os casos de uso e os requisitos foram os artefatos utilizados para a geração das treze regras de negócio. Cada uma delas é composta por:

- Identificador: padrão RN<número da regra de negócio>, por exemplo: RN01, RN02
- Descrição: a regra/política explícita
